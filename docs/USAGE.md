# 安装与反馈

日常只需要[这一条Loon订阅](https://raw.githubusercontent.com/aijc123/Bilibili-Redirect-US/main/dist/lab/BiliBili.Range.Lab.plugin)。当前是0.1.14自动版，只有“启用加速”开关。

## 安装或更新

1. 在Loon插件列表添加订阅地址；已有该地址则更新它。
2. 停用原Redirect、旧Range实验版及其他B站CDN/Range复写，只启用一份。
3. 确认MitM证书已按[Loon官方说明](https://nsloon.app/docs/category/mitm/)安装并信任，再回到B站官方App播放。

旧参数会被自动版忽略，无需逐项改设置。更新插件后若界面仍保留旧菜单，先重新打开插件；仍显示旧版本时更新/重新导入同一地址。只有诊断显示新版本不能证明下载脚本也更新：新请求进入后会记录实际处理脚本的版本。

## 怎么把结果传回来

同视频、同清晰度、同Wi-Fi播放30–60秒后，立即运行 **Bili Range 诊断**。从结果通知复制摘要，或在日志右上角分享、复制/保存文本，再粘贴到聊天。需要深入排查时补一份 **Bili Range 详细诊断**；DNS结果只有涉及解析等待时再提供。

同时附这几项即可：视频清晰度、播放倍速、首开慢/播放中卡顿/基本顺畅，以及是否换网络或拖动进度条。不用分享Cookie、账户信息或完整签名视频地址。

## 如何读短摘要

- **没有最近30秒样本**：可能暂停、已经缓冲或只出现小请求。当前速度未知，不能据此说加速失效。
- **小请求放行很多**：低码率、初始化、音频等会有小请求；直接放行是正常策略，不等于失败。插件无法确认每个小请求的实际播放器用途。
- **设置上限8，实际只有2/3片**：范围小且每片至少128 KiB，这是正常切分。
- **失败或实体不一致**：摘要列出原因，原请求会继续处理。仅接管流量的错误率不等于整段播放失败率。
- **诊断版本和请求版本不同**：先确认只启用一份插件，并更新订阅；累计记录包含旧版本，不直接比较累计数字。

4K/1.5倍速是否流畅，以实际播放为准。自动策略和诊断的技术范围见[自动版说明](../LAB-EXPERIMENT.md)；[官方Loon文档](https://nsloon.app/docs/)提供插件、脚本、MitM与DNS说明。
