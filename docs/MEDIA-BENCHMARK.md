# 手机真实媒体测速

0.1.18独立候选增加 **Bili 媒体测速**。它下载手机刚播放过的同一小段媒体，对比原地址和CDN，直接复用BTR范围核心、现有严格下载校验及HTTP重定向适配。只读DNS查询与这个主动下载测试是两个入口；日常启用开关不变。

[更新候选订阅](https://raw.githubusercontent.com/aijc123/Bilibili-Redirect-US/main/dist/candidate/BiliBili.Range.Adaptive.plugin)。原0.1.14主订阅与旧标签保留。

## 怎么运行

1. 在Loon更新候选至0.1.18，只启用一份B站CDN/Range插件。
2. 运行 **Bili 媒体测速**，看到“已准备采样”。这一步不下载媒体。
3. 回B站播放5–10秒；若已完全缓冲，可换视频或拖动产生新下载。随后暂停播放。
4. 回Loon再次运行 **Bili 媒体测速**，等待结果；如果提示仍有播放接管，等5秒再点。复制最终摘要即可。

请保持同一Wi-Fi与路由，运行期间保持播放暂停。网络变化、检测到播放接管或达到工作时间预算会停止继续测试；跨网络或检测到竞争的完成请求不作为成功速度。检查共享预算及手动运行锁是尽力控制，存储没有原子CAS，不能保证不存在竞争窗口。无需安装新App或填写CDN、线程、DNS。

## 测什么

- 原地址及最多4个CDN：最近成功节点、08c、bos、cos、hwo1按固定优先序去重，排除已作为原地址的同主机。不是15节点全面排名。
- 同一地址路径/签名、完全相同的字节范围，每次最多1 MiB；采样窗口优先保留最大已见范围，无法保证它一定是当前视频轨。
- 每个主机用随机ABBA/BAAB顺序比较配置1/8任务，每档2次；跨主机交错，整次最多20个范围请求组。每片至少128 KiB，小范围实际可能只有2–7片，摘要显示实际值。
- 原地址首先尝试。所有响应严格检查206、范围、长度、实体与同节点分片一致性，再与首个有效参考响应逐字节比较。原地址不可用时仍测CDN，但清楚标注参考来自CDN，不能声称已与原地址验证一致。
- 完整请求耗时包含解析、连接、TLS（HTTPS时）、重定向、返回等待及合并，不是单独DNS耗时、真实TTFB或持续链路容量。不读取播放器缓冲或卡顿次数。
- 分别报告每档成功/失败、尝试耗时和成功中位Mbps；失败不产生虚假的速度。原地址也由脚本下载，不等于原生App基线；两次样本和缓存不足以证明哪个方案普遍最好。

每个范围组完成全部回调才进入下一个，不模仿浏览器取消输家。正常有效范围总量最多20 MiB，单组最多8任务；服务器忽略Range、返回异常大响应或重定向时，实际流量可能增加。65秒后不再发起新组，已发出的回调继续等待，手动脚本整体timeout=90秒。测试不把结果写成自动节点/DNS偏好。

## 地址和隐私

普通播放不保存原始媒体地址。第一次手动运行明确启用采样后，才在候选独立本地存储中短暂保存一条带签名地址及允许的请求头；不另行读取Cookie、Authorization或账号资料，不保存媒体正文。原地址本身可能含签名与账号关联参数。2分钟窗口不随捕获刷新，过期后失效，在下一次相关脚本操作清理；换网络清理。开始测试前先删除本地样本，测试结束释放手动锁和自己的共享预算租约，保留其他请求的租约与统计。Loon被强制结束时不能保证清理代码执行，残留记录下次操作处理。

地址只发往原B站媒体服务器或允许的B站CDN，重定向校验继续生效；不会发往GitHub、测速网站、DNS服务商或遥测服务器。最终摘要只含主机名、请求统计与耗时，不包含路径、签名、Range偏移或IP。复制摘要反馈，不分享临时存储原文。

## 为什么这次仍不能给DNS视频排名

[Loon公开HTTP参数](https://nsloon.app/docs/Script/script_api/)有`node`和协议偏好，但没有公开的单请求连接IP覆盖项；没有确认可安全保留原域名SNI/证书校验的IP固定方法。把HTTPS URL换成IP、仅加Host头不能当成等价测试。本工具测当前路由到各主机的真实媒体交付，**不声称测过Cloudflare/Google各自返回IP的媒体吞吐**，不修改全局DNS。

## 已执行和待执行

自动检查包含：未手动启用不保存地址、采样过期/网络变化、认证请求拒绝、完整字节校验、等长错误内容拒绝、原地址失败、工作预算与竞争停止、实际生成的下载/测速/网络脚本联动。

生成的测速脚本已实际走本机HTTP完成20个1 MiB范围组、90个子请求，所有成功响应字节一致，并发峰值8。它验证下载与报告实现，**不是B站CDN或手机性能证据**。

桌面也尝试读取[历史基准公开样例](https://github.com/chrisliu298/bilibili-cdn-fix/blob/main/benchmarks.md)的最新播放信息；本轮元信息请求收到HTTP412，未取得媒体地址，未绕过限制，没有填入虚假Mbps。[本轮尝试记录](../benchmarks/public-media-desktop-attempt.json)。可用`node scripts/benchmark-public-media.mjs`在桌面另行复现；即使成功，也只能作为桌面线路结果。

你的iPhone仍需执行上面的手动入口，才能取得当前视频和线路的真实结果。0.1.17在1080高帧率、1倍速下仍卡顿的反馈保留，新工具尚不能作为问题已解决的证明。
